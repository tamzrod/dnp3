## 1. Problem

The published v0 supported profile (`active_work/supported-profile.md`) marks
`Command handler analog controls` and `types.NewAnalogControl` as **Reject**:
Group 41 and related variations are out of scope. Before this task the code did
not enforce that boundary:

- `pkg/dnp3/master/client.go` `Operate` admitted Group 41 V1–V4 by default.
- `pkg/dnp3/outstation/server.go` `WriteAnalogOutput` dispatched analog controls
  to the host `CommandHandler` by default.

The public default behavior therefore contradicted the published profile.

## 2. Fix (default-Reject with a non-default experimental opt-in)

The v0 profile is preserved as published. Group 41 is now **rejected by default**
on both sides and is reachable only through an explicit, non-default switch that
mirrors the existing `WithExperimentalEventDelivery` pattern.

| Path | Change |
|---|---|
| `pkg/dnp3/master/client.go` | `Config.ExperimentalAnalogControl` + `WithExperimentalAnalogControl()`; fail-closed object gate in `Operate` refuses G41V1–V4 with `ErrUnsupportedOption` before any wire traffic unless the switch is set. G12V1 CROB unchanged. |
| `pkg/dnp3/outstation/server.go` | `Config.ExperimentalAnalogControl` + option; `internalDataHandler.analogControlEnabled` threaded from config; `WriteAnalogOutput` fails closed before invoking the host handler or mutating state unless enabled. |

Behavioral contract:

- Default master: G41 control → `ErrUnsupportedOption`, **no** wire traffic.
- Default outstation: G41 command → error, **no** host-handler call, **never** a
  SUCCESS acknowledgement.
- Opted-in (isolated lab only): G41V1 int32 / V2 int16 / V3 float32 / V4 float64
  single-point **Direct Operate WITH response**, per-point status, exact-bit
  float echo.

### 5B.2 Matrix A — malformed G41 requests (injector -> Go outstation)

Independent injector sends one crafted DirectOperate per fresh connection. Each
request frame is CRC-valid unless explicitly marked; the injector computes the
link header CRC over the full 8-byte prefix (including sync) to match this
project's link layer, and re-implements CRC-16/DNP from the standard so it is
independent of project code.

| Case | On-wire object | Observed response | Handler writes |
|---|---|---|---|
| `pos-v1..v4` | G41 V1–V4, count 1, idx 0 | RESPONSE IIN `0x0000`, echo, status `0x00` | 1 each (4 total) |
| `idx1-v1`,`idx1-v4` | G41 idx 1 | RESPONSE IIN `0x0000`, status `0x0c` OUT_OF_RANGE | 0 |
| `trunc-v1..v4` | value payload one octet short | RESPONSE IIN `0x0100` FuncUnknown, no G41 echo | 0 |
| `long-v1` | value one octet too long | RESPONSE IIN `0x0100` FuncUnknown | 0 |
| `badqual-17` | qualifier `0x17` (unsupported) | RESPONSE IIN `0x0100` FuncUnknown | 0 |
| `var0`,`var5` | variation 0 / 5 (unsupported) | RESPONSE IIN `0x0100` FuncUnknown | 0 |
| `count2`,`count0` | count 2 / 0 (multi-point contract violation) | RESPONSE IIN `0x0100` FuncUnknown | 0 |
| `idx2` | G41 idx 2 (beyond 0..1 window) | RESPONSE IIN `0x0000`, status `0x0c` OUT_OF_RANGE | 0 |
| `fc-write` | G41 object via WRITE (func `0x02`) | RESPONSE IIN `0x0100` FuncUnknown | 0 |
| `crc-corrupt` | valid G41 but header CRC flipped | **no** APDU (frame discarded at link layer) | 0 |

The outstation accepted **exactly four** writes — the four positive controls —

### 5B.3 Matrix B — pre-send vs after-send outcomes (Go master -> C++ peer)

The fault proxy arms only once a DirectOperate is on the wire, then withholds the
response (`drop-response`) or tears the path down (`close-after-request`). The
public Go master client drives each scenario.

| Case | Fault trigger | Observed master outcome | Quarantine | Peer writes |
|---|---|---|---|---|
| `presend-notconn` | Operate before Connect | `not connected` (definite pre-send) | no | 0 |
| `pass` | proxy transparent | `status=success` | no | 1 |
| `presend-cancel` | ctx cancelled before send | `context canceled` (definite pre-send); follow-up admitted | no | 1 (follow-up) |
| `after-send-drop-response` | response withheld after send | `control outcome unknown` (timeout) | yes; 2nd Operate refused | 1 |
| `after-send-close-after-request` | disconnect after send | `control outcome unknown` (transport closed) | yes; 2nd Operate refused | 1 |

The peer accepted **exactly four** writes: the four legitimate `pass` /
`presend-cancel`-follow-up commands. Each after-send case wrote exactly once and
was **never blindly retried or executed twice**; the second control was refused
as quarantined. `decoded/decoded-B.txt` shows the after-send connections carry
the request frame and **no** response frame on the wire.
