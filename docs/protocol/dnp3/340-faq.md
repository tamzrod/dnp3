# DNP3 Protocol FAQ

## General Questions

### Q: What is DNP3?
DNP3 (Distributed Network Protocol 3) is a communication protocol designed for SCADA systems in electrical utilities and industrial automation. It is standardized as IEEE 1815.

### Q: What does DNP3 stand for?
Distributed Network Protocol 3. It was originally developed by Westronic (later GE Harris) in the 1990s.

### Q: What is the difference between DNP3 and IEEE 1815?
IEEE 1815 is the standardized version of DNP3. They are the same protocol; IEEE 1815 is the official standard name.

### Q: What is the current version of the standard?
IEEE 1815-2012 with Technical Corrigendum 1 (published 2016).

## Protocol Questions

### Q: What transport layers does DNP3 use?
DNP3 typically runs over TCP/IP or serial (RS-232/RS-485). The protocol itself doesn't specify the physical layer.

### Q: What is the maximum DNP3 frame size?
The maximum data link frame is 292 bytes of user data. Application messages larger than ~281 bytes are fragmented.

### Q: What is the difference between Variation 0 and other variations?
Variation 0 means "use the device default variation." Specific variations (1, 2, 3, etc.) indicate precise encoding formats.

### Q: What is FCB?
Frame Count Bit - a data link layer confirmation mechanism where the master toggles a bit on each confirmed frame.

### Q: What is the difference between CON and FCB?
CON (Confirmation) is an application layer flag requiring application-level acknowledgment. FCB is a data link layer mechanism for frame delivery confirmation.

## Data Questions

### Q: How are analog values encoded?
Analog values can be encoded as 16-bit integer, 32-bit integer, 32-bit float (IEEE 754), or 64-bit double. The variation specifies the encoding.

### Q: What do quality flags mean?
Quality flags indicate data validity. The ONLINE flag (0x01) indicates fresh, valid data. Other flags indicate offline, restart, communication loss, etc.

### Q: How do events work?
Events are generated when data changes. For binary, any change generates an event. For analog, changes must exceed the configured deadband.

### Q: What are classes?
Classes (0-3) are priority groupings for data. Class 0 is static data, Classes 1-3 are events of decreasing priority.

## Communication Questions

### Q: What is unsolicited response?
An unsolicited response is sent by an outstation without a prior master request, typically when events are generated and unsolicited is enabled.

### Q: Do I need to enable unsolicited?
No. Unsolicited is optional. You can poll for all data without enabling unsolicited responses.

### Q: What is select-before-operate?
A control pattern where SELECT reserves a control point, then OPERATE executes it. This provides safety by separating reservation from execution.

### Q: Can I use direct operate instead of select-operate?
Yes, DIRECT_OPERATE combines both steps. However, select-operate is safer for critical controls as it provides an intermediate checkpoint.

## Security Questions

### Q: Does DNP3 have security?
Yes, IEEE 1815-2012 added Secure Authentication with challenge-response and message authentication codes.

### Q: Should I enable Secure Authentication?
For production critical infrastructure, yes. Secure Authentication prevents unauthorized control operations.

### Q: Does DNP3 encrypt traffic?
The standard doesn't specify encryption. Use TLS/IPsec at the network layer for confidentiality.

## Implementation Questions

### Q: Do I need to implement all function codes?
No. Implement required functions (READ, WRITE, SELECT, OPERATE, CONFIRM) and return NOT_SUPPORTED for others.

### Q: How do I handle Variation 0 requests?
Return your device's default variation for that group. Document what your defaults are.

### Q: What happens if I receive an unknown function code?
Return a response with appropriate error code (typically NOT_SUPPORTED).

### Q: Do I need to implement fragmentation?
Yes, if you need to send messages larger than ~281 bytes. Smaller messages can use single fragments.

## Troubleshooting Questions

### Q: Why are my events not being sent?
Check: 1) Events are enabled, 2) Unsolicited is enabled, 3) Event buffer isn't full, 4) Class assignment is correct.

### Q: Why is my control rejected with NO_SELECT?
Some devices require SELECT before OPERATE. Send SELECT first, then OPERATE.

### Q: Why do I get FCB errors?
FCB state is out of sync. Send RESET_LINK_STATIONS to clear state on both sides.

### Q: Why are timestamps inaccurate?
Outstation clock may need synchronization. Send TIME_SYNC or use DELAY_MEASUREMENT for accuracy.

## Interoperability Questions

### Q: How do I ensure interoperability?
Follow IEEE 1815 exactly. Test with multiple implementations. Use conformance test suites.

### Q: Can DNP3 devices from different vendors communicate?
Yes, if they both implement IEEE 1815 correctly. Use standard groups, variations, and function codes.

### Q: What variations should I support?
Support common variations: Binary (G1V1, G1V2), Analog (G30V1, G30V2, G30V3), Counter (G20V1, G20V2).
