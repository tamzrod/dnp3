# FIX-002: Multi-Connection Support for Outstation

**Issue**: Single transport reused, multi-master broken, errors swallowed  
**Fix**: One outstation instance per connection, proper connection tracking  
**Severity**: HIGH

## Problem

The old implementation:
1. Had single `t.conn` field that overwrote on new accept
2. Errors swallowed without logging
3. `Run()` blocked indefinitely
4. Multi-master support completely broken

```go
// Old: Single transport
t.conn = conn  // Overwrites previous!
```

## Solution

Each accepted connection now gets:
1. Its own TCPTransport instance
2. Its own Outstation instance
3. Its own goroutine
4. Proper logging

### Key Changes

1. **Connection Tracking**: `connections` map tracks all active connections
2. **Per-Connection Outstation**: `handleConnection()` creates dedicated outstation
3. **Logging**: All accept/close events logged
4. **Graceful Shutdown**: All connections closed on Stop()

## Architecture

```
Server
├── listener (net.Listener)
├── connections map[uint64]*outstationInstance
│   ├── Instance 1 → Outstation + Transport + goroutine
│   ├── Instance 2 → Outstation + Transport + goroutine
│   └── Instance N → Outstation + Transport + goroutine
```

## New Types

```go
type outstationInstance struct {
    id        uint64
    masterAddr net.Addr
    outstation *outstation.Outstation
    transport  transport.Handler
    done      chan struct{}
}
```

## Files Modified

| File | Change |
|------|--------|
| `pkg/transport/tcp.go` | Added SetConn/SetListener methods |
| `pkg/dnp3/outstation/server.go` | Complete rewrite of accept loop |

## API Changes

- `ActiveConnections()`: New method to get count of active connections
- `SetDataHandler()`: Now updates all active connections

## Multi-Master Support

Multiple masters can now connect to the same outstation:
- Each master gets isolated session
- No connection overwriting
- Independent request/response handling
