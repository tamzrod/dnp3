# FIX-001: Standard DNP3 Framing for TCPTransport

**Issue**: TCPTransport used custom 2-byte length prefix, not standard IEEE 1815  
**Fix**: Removed length prefix, use standard DNP3 DLL framing  
**Severity**: CRITICAL

## Problem

The old TCPTransport added a 2-byte length prefix to all data:

```go
// Old: Custom length prefix
length := uint16(len(data))
header := make([]byte, 2)
binary.BigEndian.PutUint16(header, length)
t.conn.Write(header)
t.conn.Write(data)
```

This is NOT standard DNP3. Standard DNP3 frames start with sync bytes (0x05 0x64).

## Solution

TCPTransport now sends/receives standard DNP3 DLL frames:

```go
// New: Standard DNP3 framing
// Send: Just write the frame (caller provides proper DLL frame)
// Receive: Find sync bytes, read length, read rest
```

### Key Changes

1. **Send**: Sends data directly without length prefix
2. **Receive**: 
   - Reads until sync byte 1 (0x05) found
   - Reads sync byte 2 (0x64)
   - Reads length byte
   - Reads rest of frame

## Files Modified

| File | Change |
|------|--------|
| `pkg/transport/tcp.go` | Rewrote Send/Receive for standard framing |

## Standards Compliance

Now complies with IEEE 1815-2012 Section 5.2:
- Frames start with 0x05 0x64
- Self-delimiting via sync bytes + length field
- No external length prefix

## Testing

Standard DNP3 devices and tools (Wireshark, OpenDNP3) should now be able to communicate with this implementation.
