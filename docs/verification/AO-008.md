## 2. Implementation (bounded to the Phase B contract)

### 2.1 Stable opt-in, both roles (`pkg/dnp3/master/client.go`, `pkg/dnp3/outstation/server.go`)

- Added `master.WithAnalogControl()` and `outstation.WithAnalogControl()`,
  each returning the existing `ConfigOption` and setting the same explicit
  `ExperimentalAnalogControl` flag. **OFF by default.**
- `WithExperimentalAnalogControl()` is retained on both roles as an explicit,
  backward-compatible alias enabling exactly the same path. No default
  enablement, no object-group widening, no mode widening.
- The outstation fail-closed message now names the stable option first and the
  legacy alias second. The master/outstation opt-ins remain independent.

### 2.2 Explicit legacy-carrier rejection (`pkg/dnp3/master/client.go`)

The Phase A finding was that the legacy `types.NewAnalogControl(float64)`
exclusion was only *implicit* (it failed because `controlInt32Value` refuses a
float64 carrier). Phase B adds an explicit carrier-type check at the G41
Variation 1 gate: when the opt-in is on and the value is
`*types.AnalogCommandValue`, the command is refused with `ErrUnsupportedOption`
before any wire traffic. This does not depend on coercion strictness, so a
future float→int32 coercion cannot silently admit a truncated legacy value.
V4 still admits `AnalogCommandValue` by design (pinned by
`TestG41V4StillAdmitsGenericFloat64Carrier`).

### 2.3 Documentation coherence (`pkg/dnp3/types/commands.go`)

`NewAnalogControl`'s doc comment now states that the ambiguous float64 carrier
stays rejected even under the explicit opt-in.

No change to G12V1/CROB, Class-0, events, SBO, no-response, WRITE, multi-point,
NaN/Inf/range/echo strictness, or the after-send quarantine policy.
