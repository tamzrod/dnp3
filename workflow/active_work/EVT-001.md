## Authoritative layouts

Wire layouts below are the IEEE 1815 object sizes that match this repository's already verified static flag-then-little-endian pattern (Group 30 Variation 1 and Group 20 Variation 1 comments in `internal/outstation/outstation.go`, pinned OpenDNP3 3.1.2 `GroupVariation.h` names). `docs/protocol/dnp3/150-events.md` is not authoritative: it mislabels Group 32 variations and is not followed.

DNP time is 48-bit little-endian milliseconds since 2000-01-01 00:00:00 UTC, the same epoch as Group 50 Variation 1. A time before that epoch, or a millisecond count that does not fit in 48 bits, is an error. A zero `time.Time` selects the without-time variation. Relative time (Group 2 Variation 3 and the other relative-time variations) is **unsupported**. There is no Group 52 common-time base in this task.

Multi-octet numeric fields are little-endian. Event responses use qualifier `0x17` (8-bit count + 8-bit index) for indexes 0–255. Indexes above 255 are rejected. Qualifier `0x28` stays the existing control-path count+index encoding and the object-header helper's start/stop encoding. This task does not overload that helper.

Class assignment objects are Group 60 Variation 2 (Class 1), Variation 3 (Class 2), and Variation 4 (Class 3), qualifier `0x06`. That qualifier encodes as three octets and no range byte, matching `ObjectHeader.Encode` and the Group 60 Variation 1 golden `{60, 1, 0x06}`.

### Binary input events — Group 2

Flag octet: state in bit `0x80`. Quality in the low bits: ONLINE `0x01`, RESTART `0x02`, COMM_LOST `0x04`, REMOTE_FORCED `0x08`, LOCAL_FORCED `0x10`, CHATTER `0x20`.

| Variation | Layout | Size |
| --- | --- | --- |
| 1 | flags | 1 |
| 2 | flags + 6-byte absolute time | 7 |
| 3 | relative time | unsupported |

### Analog input events — Group 32

Not Group 31 (frozen analog). Flag octet: ONLINE `0x01`, RESTART `0x02`, COMM_LOST `0x04`, REMOTE_FORCED `0x08`, LOCAL_FORCED `0x10`, OVER_RANGE `0x20`, REFERENCE_ERR `0x40`.

| Variation | Layout | Size |
| --- | --- | --- |
| 1 | flags + int32 | 5 |
| 3 | flags + int32 + 6-byte absolute time | 11 |
| 2, 4, 5, 6, 7, 8 | other widths / float / relative time | not in this task |

Group 32 Variation 1 matches static Group 30 Variation 1 (flags, int32, little-endian). Float event variations are not implemented here.

### Counter events — Group 22

Not Group 21 (frozen counters). Flag octet: ONLINE `0x01`, RESTART `0x02`, COMM_LOST `0x04`, REMOTE_FORCED `0x08`, LOCAL_FORCED `0x10`, ROLLOVER `0x20`, DISCONTINUITY `0x40`.

| Variation | Layout | Size |
| --- | --- | --- |
| 1 | flags + uint32 | 5 |
| 5 | flags + uint32 + 6-byte absolute time | 11 |
| 2, 6 | other widths / relative time | not in this task |

These flag bits are the event-object bits. They are not the nonstandard static counter constants already used for Group 20 Variation 1. Those static constants and goldens stay as they are.

### Function codes

Pinned OpenDNP3 3.1.2 `FunctionCode.h`: ENABLE_UNSOLICITED `0x14`, DISABLE_UNSOLICITED `0x15`, RESPONSE `0x81`, UNSOLICITED_RESPONSE `0x82`, CONFIRM `0x00`. The previous in-repo constants 41 and 42 were not those codes. EVT-001 sends `0x14` and `0x15`. Confirm, response, and unsolicited-response codes were already correct.

`FuncGetIdentifier` remains the decimal constant 21, which now aliases `0x15`. This stack does not send that identifier function. The name of wire `0x15` is DISABLE_UNSOLICITED.

An enable or disable request with empty data enables or disables all three classes. A request that contains objects changes only Group 60 Variations 2/3/4. The existing nil-data enable test stays valid.

## Architecture

- One event queue per outstation server, shared by the single accepted connection (`MaxConnections` stays 1). A disconnect does not drop unconfirmed events. The next connection uses the same queue.
- `EventQueue.Add` still rejects the newest event when that class is at `maxSize/3`. It does not drop the oldest. That behavior is locked by `TestEventQueueOverflow`. `IIN.BufferOverflow` follows the existing GenerateEvent rule: set when the queue reports full.
- Each accepted event gets a monotonic sequence. A class snapshot is ordered by timestamp when both events have timestamps, otherwise by insertion sequence.
- Several events may share one point index.
- The caller's timestamp is stored on the event and copied into the encoded fragment. A retry sends those same bytes. Transmit time is not substituted.
- Solicited Group 60 Variation 2/3/4 reads return queued events of that class and then remove them. The response has CON clear, so the stack does not wait for an application confirm on that read. An empty class read stays object-less. It does not fall back to static data.
- Existing `buildPollRequest` bytes stay put. Class 1/2/3 polls remain count-0 Group 2/32/22 Variation 1. A count of zero returns no events and does not dump static points.
- The old `buildBinaryInputEventData`, `buildAnalogInputEventData`, and `buildCounterEventData` helpers read static points with non-conformant groups and endianness. Class reads and Group 2/22/32 reads do not call them.
- Unsolicited responses use function `0x82`, FIR+FIN+CON+UNS, and a 4-bit sequence that is separate from the solicited sequence. The sequence starts at 0 and advances only after a matching confirm. Retries reuse the sequence and the encoded bytes.
- Confirm is function `0x00`. A matching confirm removes the in-flight events. A duplicate confirm is ignored. A mismatched sequence is ignored and the in-flight fragment stays.
- Confirm timeout is 2 seconds. At most two retries follow the first send (three sends). After that the outstation stops, leaves `awaiting` clear, and keeps the buffer. A later publish or enable may try again.
- A solicited class read that takes in-flight events cancels the confirm wait. Those events are not retried.
- A send error clears `awaiting` and keeps the buffer. Acceptance by TCP is not treated as master confirmation.
- TCP `Send` and `Receive` do not hold the connection mutex across I/O, so a publish may send while `Run` is blocked in `Receive`. There is only one reader.
- The master confirms an in-order unsolicited fragment and delivers it once. A duplicate of the last accepted sequence is confirmed and not delivered again. Any other sequence is not confirmed and not delivered. The master accepts the first unsolicited sequence of a connection, then requires the next sequence.
- If an unsolicited frame arrives while the master is waiting for a solicited response, the master confirms and delivers it and keeps waiting. It is not the solicited response.
- `WatchUnsolicited` is an idle receive loop. It is not a class poll. It uses the same request lock as reads, one receive at a time, so it does not add a second reader.
- Public `EnableUnsolicited` and `DisableUnsolicited` send `0x14` / `0x15` with Group 60 Variations 2, 3, and 4, qualifier `0x06`.

## IIN freeze — historical note, then lifted for the bit map

The implementation checkpoint below recorded the MEXT-019 freeze: bit 0 was the MSB inside each IIN octet, so class 1/2/3 were `0x40` / `0x20` / `0x10` and buffer overflow was `0x10` in octet 2. Pinned OpenDNP3 3.1.2 `IINField.h` uses the opposite significance. The EVT-001 completion authorization lifted that freeze for the bit-position correction only. Both octets now match the OpenDNP3 LSB map. Class 1 is octet 1 mask `0x02`. Buffer overflow is octet 2 mask `0x08`. Named flag meanings are unchanged. The isolated class-0 observation `IIN lsb=02 msb=08` is recorded in `docs/verification/EVT-001-OPENDNP3.md`.

## Public API

Outstation server, without frame construction:

- `PublishBinaryEvent(index uint16, value bool, quality uint8, class EventClass, at time.Time) error`
- `PublishAnalogEvent(index uint16, value int32, quality uint8, class EventClass, at time.Time) error`
- `PublishCounterEvent(index uint16, value uint32, quality uint8, class EventClass, at time.Time) error`

`quality` is the event flag octet defined above, not a remapping of the public static `QualityFlags` constants. Binary `value` is carried in flag bit `0x80`.

Master client:

- `EnableUnsolicited` / `DisableUnsolicited` send the wire requests when connected.
- `SetUnsolicitedHandler` registers the delivery callback.
- `WatchUnsolicited(ctx)` receives unsolicited fragments while idle.

The published supported profile still describes unsolicited reporting as rejected. The completion checkpoint corrects only the MEXT-019 IIN row. In-repo event behavior and that profile sentence disagree until a later, separate promotion. Callers must not treat this package as a conformance claim.
