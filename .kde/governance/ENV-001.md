## Purpose

This policy establishes requirements for verifying the runtime environment before investigation work begins. It ensures that agents verify toolchain availability and do not promise test execution without first confirming the environment supports it.

---

## Policy Statement

### Rule 1: Pre-Investigation Verification

Before ANY investigation work begins, the agent **MUST** verify:

1. **Runtime State**: `.kde/runtime/state.json` shows "ready"
2. **Required Tools**: All project-specific toolchains are available
3. **Project Dependencies**: Required packages/dependencies are installed

### Rule 2: Environment-Specific Verification

For **Go Projects** (like DNP3), verify:

- [ ] `go` command is available (`which go` returns path)
- [ ] Go version meets minimum requirement (check go.mod)
- [ ] Dependencies available (`go mod download` or `go mod verify`)

For **Other Projects**, adapt verification to:

- [ ] Primary language toolchain available
- [ ] Package manager accessible
- [ ] Project dependencies installed

### Rule 3: Promise Prohibition

An agent **MUST NOT** promise to run tests or validation if:

1. The required toolchain is not verified as available
2. The project dependencies are not confirmed installed
3. The environment verification has not been performed

### Rule 4: Failure Documentation

If environment verification fails:

1. **Document** the failure with specific details
2. **Report** the limitation to the user immediately
3. **Do NOT** make promises about test execution or validation
4. **Proceed** with investigation only for documentation/analysis tasks

## Verification Procedures

### Pre-Investigation Checklist

```markdown
## Environment Verification Checklist

### Runtime State
- [ ] .kde/runtime/state.json exists
- [ ] status is "ready"
- [ ] all modules are "loaded"

### Toolchain (Go Project)
- [ ] `which go` returns a path
- [ ] `go version` shows version >= 1.21
- [ ] `go env GOPATH` is set

### Dependencies
- [ ] go.mod exists
- [ ] `go mod verify` passes
- [ ] No missing dependencies reported

### Result
- [ ] Environment VERIFIED - proceed with investigation
- [ ] Environment FAILED - document and report limitation
```

### Verification Commands

For Go projects, use these commands:

```bash
# Check Go availability
which go && go version

# Check Go module
cd /path/to/project
go mod verify

# Check build capability
go build ./...
```

## Compliance Verification

### Check: Pre-Investigation Verification

Every investigation **MUST** have evidence of environment verification:

- [ ] Investigation documents runtime state check
- [ ] Investigation documents toolchain verification
- [ ] Investigation documents dependency check

### Check: Promise Prohibition

Verify that:

- [ ] No test execution promised without verification
- [ ] Any limitations are documented in investigation
- [ ] User is informed of environment limitations

## Violations

| Violation | Severity | Example | Remediation |
|-----------|----------|---------|-------------|
| Missing runtime state check | HIGH | Didn't verify state.json | Add verification step |
| Missing toolchain verification | HIGH | Promised tests without `which go` | Add check before promises |
| Unfulfilled test promise | CRITICAL | Said "I'll run tests" but Go missing | Document limitation first |
| Missing dependency check | MEDIUM | Didn't run `go mod verify` | Add verification step |

---

## Enforcement

1. **Bootstrap Gate**: Environment verification is part of Bootstrap Module 0
2. **Investigation Documentation**: All investigations must document verification
3. **Meta-Investigation**: Violations trigger meta-investigation (per KDE-INV-051)
